# 第 03 轮　IQ 出口、功能单元、寄存器端口与推测唤醒

在选定 IQ 的每个 IssuePort 上提取 fu 与 rp，对应到 FuncUnitConfig.py 的 opList、IntRD/FpRD 的端口号及优先级。按物理寄存器 bank 与 ID 去重统计。C++ 的 useRegfilePort 接受这组端口和优先级进行仲裁。当前声明未给出独立写端口连接，检查器将写端口列为未知。

| 指标 | GEM5-1 | zenas-dev |
|---|---:|---:|
| 整数 / 访存 / 浮点向量出口 | 11 / 8 / 4 | 8 / 7 / 4 |
| 出口总数 / 不同 FU 类型 | 23 / 24 | 19 / 25 |
| 去重整数 / 浮点读端口 ID | 31 / 14 | 9 / 14 |
| 已确认源 IQ → 目的 IQ 对（含本队列） | 9 | 92 |

GEM5-1 的整数 IQ 出口 0–7 可执行整数 ALU 等类别，出口 8–10 绑定 IntBRU。访存出口有 4 个 ReadPort、2 个 WritePort 和 2 个 StoreDataPort。zenas-dev 则在 4 个整数 IQ 上布置 8 个出口，在 4 个访存 IQ 上布置 7 个出口。两模型的浮点读端口编号均为 0–11、16、17。FU 类型统计表示不同描述类，在多个端口重复引用的设备只计一次。

FUScheduler.py 指定的唤醒源、目的分别进入 issue_queue.cc 的 wakeMatrix。模型显式设置的三队列网络有 3×3 个有向对。十二队列模型中 intIQ3 可唤醒 fpIQ0，fpIQ0 的发送列表并不包含 intIQ3。输出保留每条有向路由和其源码。普通流水指令和 Load 均要满足各自的运行期条件，源码映射只描述配置允许的连通性。

独立执行两个输入的 --through-round 3 并重新读取 JSON 和 HTML 产物。分别核对三组出口计数、有效 FU 类及操作类别、每个读端口 ID 和优先级、唤醒矩阵的有向性、Issue 子图的仲裁与唤醒连线。两结果均通过。源码定位包括两个输入 configs/common/FUScheduler.py 的 HUANJIANV1Scheduler 类，src/cpu/o3/FuncUnitConfig.py 的 IntBRU.opList，以及 src/cpu/o3/issue_queue.cc 的 IssueQue::selectInst、Scheduler::specWakeUpDependents、Scheduler::useRegfilePort。

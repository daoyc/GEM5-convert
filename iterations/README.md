# GEM5-1 与 zenas-dev 十轮转换记录

打开 [GEM5-1](../GEM5-1.html) 或 [GEM5-2 · zenas-dev](../GEM5-2.html)。总览里的 Issue 卡片直接给出 IQ 总量。点击卡片，在“结构覆盖与模型对照”中加载另一份 HTML，可看同一项在两棵源码中的值、条件和位置。选中 MMU、IFU、Commit 或缓存模块可按同样方式核查。两页均可单独分发。

| 选中结构 | GEM5-1 | GEM5-2 · zenas-dev |
|---|---|---|
| 整数 / 访存 / 浮点向量 IQ 容量 | 192 / 192 / 160，合计 3 个队列 | 72 / 72 / 128，合计 12 个队列 |
| 发射出口 / 定向推测唤醒队列对 | 23 / 9 | 19 / 92 |
| 去重的整数 / 浮点寄存器读口编号数 | 31 / 14 | 9 / 14 |
| L2 TLB miss 启动遍历 | 调用传入计算的 root_level | 对应调用传入 2，walker 内另有 SV48 条件 |
| ideal 下 Decode / Rename 宽度 | 10 / 10 | 8 / 8 |
| 默认 ROB → ideal ROB | 160 → 384 | 160 → 256 |
| 取指驻留窗口回放 | 默认关闭；ideal + BTB 开启 | 检查的 CPU 参数和 Fetch 实现缺失 |

两份默认总览各有 **15 个模块、27 条有向逻辑边**。GEM5-1 下钻后有 125 个节点、153 条边（各子图分别统计，含边界节点）；GEM5-2 有 122 个节点、150 条边。两个模块清单各含 228 项。全部节点都可关联源码图，场景的每一步都绑定有向边。两份源码分别读出 1,225 个声明和 2,422 / 2,423 条声明关系。完整边界可查[逐模块覆盖清单](COVERAGE.md)。

[累计重建记录](conversions.json)保存第 1–10 轮每份页面的摘要、图大小、场景/步骤数、覆盖状态、诊断以及 HTML 哈希。运行 `python -B iterations/rebuild.py` 可依次重新执行这 20 次转换。`--round N --log PATH` 可单独复现某一阶段。源码文件不包含配置运行时的动态取值、队列占用或实际事件顺序。本次运行输入及 trace 验收使用合成样本；实际程序的逐事件回放需导入对应 trace。

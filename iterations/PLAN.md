# 从 GEM5 源码核对 Core Atlas 的十轮迭代方案

以 `D:/huanjian-project/stage-two/GEM5-1` 为主样本，以 `D:/codex-project/model-convert/zenas-dev` 为差异对照。两者分别输出项目根目录的 `GEM5-1.html` 与 `GEM5-2.html`。每轮都从两份输入转换，读取产物中真正嵌入的数据，记录差异、证据和仍未知的部分。

| 轮次 | 核对范围 | 验收问题 |
|---|---|---|
| [01](01.md) | 模型入口和基线 | 从配置入口能否追到 CPU、调度器及条件覆盖？总览模块、子图、场景分别覆盖多少？ |
| [02](02.md) | 发射队列 | 实际选择了哪些队列？逐队列容量、入口、出口与配置定义是否一致？ |
| [03](03.md) | 执行资源与依赖 | 是否能从队列追到发射端口、FU、寄存器读口及定向唤醒？ |
| [04](04.md) | 预测与取指 | 活动预测器、目标队列、取指和恢复接口是否能在相应分支找到调用依据？ |
| [05](05.md) | 地址翻译 | 指令侧、数据侧的命中、页表遍历和回填是否有相应的端口与条件？ |
| [06](06.md) | 提交与恢复 | 正常退休、分支恢复和精确异常能否分别追踪？ |
| [07](07.md) | 访存与缓存 | LSQ、缓存、互联和内存的关键动作是否有来源，条件连接是否单列？ |
| [08](08.md) | 配置优先级 | 条件赋值、源码默认、实例导出和缺失字段能否区分？ |
| [09](09.md) | 回放与交互 | 场景步骤是否唯一匹配有向边？离线页能否下钻、悬停高亮、播放和定位源码？ |
| [10](10.md) | 独立重建和回归 | 单独的打包转换器能否从两份输入重建 HTML，并通过与原始源码独立比对的断言？ |

结构按所选配置梳理。为声明、子组件、实例、调用或端口关系记录可核查的来源。推导得到的拓扑要保留依据和启用条件，无法解析的值和连接留在缺口清单。场景须注明源码演示或运行事件，保留从画面返回源码的途径。验收时同时交付两份离线页面、十轮记录、复核脚本与剩余限制。

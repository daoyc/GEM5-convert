# 第 02 轮　实际选中的 Issue Queue

转换器从 CPU 选中的调度器类解析 IQs 表达式及三个列表，逐个读取 IssueQue 的名称、size 和 inports，求值整数加法与乘法，并为每个队列保留独立配置位置。Issue 子图增加整数、访存、浮点/向量三组节点，六条带 C++ 依据的连线分别表示按操作类别入队与就绪选择。

| 源码与队列组 | 队列数 | 容量总项数 | 配置输入端口数之和 |
|---|---:|---:|---:|
| GEM5-1 整数 / 访存 / 浮点向量 | 1 / 1 / 1 | 192 / 192 / 160 | 10 / 10 / 10 |
| zenas-dev 整数 / 访存 / 浮点向量 | 4 / 4 / 4 | 72 / 72 / 128 | 8 / 8 / 8 |

GEM5-1 的选用声明为 configs/common/FUScheduler.py 第 46、91、110 行，第 130 行将三个列表连接起来。zenas-dev 第 31–92 行逐队列声明，启用的列表在第 93 行组合；同文件内其他调度器类未纳入。GEM5-1 总容量为 544 项，zenas-dev 为 272 项。输入端口和仅描述各队列的配置容量，整核分派速率还受流水级带宽限制。

使用 convert_model.py 对两个实际根目录执行 --through-round 2，并为每个输入写出独立 HTML 与 JSON。在重新读取的 JSON 上分别断言三组的容量、端口、队列数、C++ 有向边、每个队列的真实源码文件与行内容。两份输出均通过；发射页摘要可直接区分三队列和十二队列。

# 第 09 轮　让回放绑定当前模型的有向边

第 8 轮的结构图已经区分两种 IQ 和有条件的取指路径。检查事件时发现，仅凭两个模块名无法判断是普通写回、误预测恢复，还是同一对实例的另一条端口连接。因此，本轮在所有模块扩展完成后统一核验场景，并补入整数、访存、浮点三组 IQ 的入队选择、推测唤醒和寄存器读口仲裁演示。

**实现与依据**

- 每个已接受的场景写入视图 ID 与“源码演示”来源，每一步保留有向边 ID、发送点、接收点和该边的源码定位。核验图内端点、方向、证据和 ID 唯一性。两个输入的队列选择、推测唤醒与读口仲裁分别落在 `src/cpu/o3/issue_queue.cc:556`、`:1278`、`:1359`。两套模型的唤醒对来自各自的 `configs/common/FUScheduler.py`。
- 导入 trace 先对整个序列校验，成功后才替换场景。旧格式允许同方向唯一端点对。响应可沿实际端口反向返回；逻辑流须能找到相应方向的边。返回原始 tick，同 tick 的步骤沿文件顺序播放。
- GEM5-1 的窗口填充在 `src/cpu/o3/fetch.cc:641` 调用 `recordFetchResidentWindow`。导入的实例同时满足回放开关、双目标取指、BTB 条件时启用受控演示；zenas-dev 没有相应实现。

**重建与结果**

在项目根目录运行 `python iterations/rebuild.py --round 9 --log round9-check.json` 可单独重做两次转换。完整的累计结果见[转换记录](conversions.json)。两份默认图各有 57 个可播放场景、235 步。GEM5-1 另保存 1 个默认关闭的三步场景。选择 ideal 与 BTB 后，两个页面分别通过 58 个场景 / 238 步与 57 个场景 / 235 步检查。

使用本机的 Node、Playwright 和 Chromium，运行以下命令可在最终页面复核回放。Playwright 若使用系统 Chrome，可将 `CHROME_PATH` 设为可执行文件路径。

```powershell
node converter/verify_zenas_page.cjs GEM5-1.html
node converter/verify_zenas_page.cjs GEM5-2.html
node iterations/verify_comparison.cjs
```

浏览器逐步核对列表、激活边、箭头端点、发送与接收卡片，以及运动轨迹在五个位置与线身重合；播放时还测量了移动光点的位置变化。有效 trace、端点唯一、平行端口歧义、反向逻辑边、边 ID 缺失和超出 JavaScript 安全整数的 tick 均通过测试。错误提示包含失败的端点或 ID，并保留原事件。比较测试覆盖两页互载、逐核开关、实例字段缺省、私有 L2、共享内存通道，以及切回源码。所有外部网络请求在测试期间均被拦截。

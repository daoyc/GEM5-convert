# 第 10 轮　独立打包、源码复核与离线验收

正式交付采用同一个 `GEM5-converter.pyz`。两个空工作目录各复制一份包，分别以主源码和 zenas-dev 为输入。转换完成时，每个目录只有复制的包和新生成的 HTML。清理临时目录后，两份交付 HTML 仍可独立打开。同步到 model-view 的源码按该工程的查看器目录重新打包，两处生成的包逐字节相同。

**可复验步骤**　从 model-convert 根目录运行。第一条重建打包文件，第二条将重新生成两个约定文件名的交付页。去掉 `--publish` 可仅在临时目录验证。

```powershell
python -B converter/build_portable.py
python -B iterations/rebuild.py --publish
python -B iterations/verify_sources.py --huanjian-html GEM5-1.html --zenas-html GEM5-2.html
python -B iterations/coverage_report.py
node converter/verify_zenas_page.cjs GEM5-1.html
node converter/verify_zenas_page.cjs GEM5-2.html
node iterations/verify_comparison.cjs
python -B iterations/source_guard.py iterations/source-hashes.json D:/huanjian-project/stage-two/GEM5-1 D:/codex-project/model-convert/zenas-dev
```

**独立源码断言**　`verify_sources.py` 只使用 Python 标准库，独立解析入口选中的 CPU、scheduler 类体、逐队列容量与端口、FU/读口优先级、定向唤醒网络。它从预测器 C++ 构造函数读取活动注册，从 TLB/walker 的真实调用核验起始层，从 CPU 类声明和 ideal 配置分支计算 ROB、LQ、SQ、Store Buffer 与驻留窗口开关。它用隔离 Python 重新转换默认与 ideal + BTB 四组输入，验证每一步的端点与文件行，并将重新生成的默认模型数据与正式发布页的嵌入数据逐项比较。两份输入、四组转换均通过。关键位置包括两份 `configs/common/FUScheduler.py:29`、GEM5-1 的 `src/arch/riscv/tlb.cc:1898` 与 zenas-dev 的同文件 1867 行，以及两份配置分别在 `configs/example/xiangshan.py:334` 与 329 行的 ideal ROB 覆盖。

**浏览器验收**　Chrome 直接以 `file://` 打开每个交付文件，禁止加载其他 URL。两份页面均覆盖总览与全部 15 个模块，每个模块至少点验一个内部节点和一条边的源码位置，并展开边的离线源码片段。默认可播放场景各 57 个、235 步。另验四种条件来源（源码默认、ideal 配置、运行 CPU、运行字段缺省），包括两个私有 L2 和两个共享内存通道。旧版 `core-atlas/1` 的导入、名称搜索与对象浏览通过；两个端口端点相同且向量下标交叉的配置通过稳定边 ID 核验。移动宽度、播放及失败 trace 的结果见[第 09 轮](09.md)。

**范围**　正式页面以 `configs/example/xiangshan.py` 的默认条件生成。本轮没有运行 gem5 仿真或采集程序 trace。运行导入使用合成的三核配置与平行端口样本。RAT 分库、寄存器独立写端口、运行中实际采用的仲裁和分页模式仍需相应源码或运行证据。模块的具体抽象、条件、缺失与未知项见[逐模块清单](COVERAGE.md)。

对输入树 10,305 和 10,282 个文件分别按相对路径和文件内容做 SHA-256 汇总，最终值与转换前完全一致。详见[输入摘要](source-hashes.json)。

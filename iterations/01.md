## 归属与流水级参数补验

两份模型各使用默认条件和 --set ideal-kuanglangv1=true 重跑 --through-round 1，共得到四套独立 JSON/HTML。每套都逐一核验 15 个模块的配置对象或 C++ 成员归属，并将证据文件、实际行号和行文本与输入源码比对。

| 模块 | 已核对的归属 / 边界 |
|---|---|
| BPU、FTQ | CPU 配置的 branchPred 子对象；FTQ 合并在选中预测器的 fetchTargetQueue 成员 |
| IFU、Decode、Rename、Issue、Commit | o3::CPU 的 fetch、decode、rename、iew、commit 成员；节点分别引用 cpu.hh 的成员声明 |
| LSU | IEW 内的 ldstQueue 成员 |
| MMU | CPU 类继承 RiscvO3CPU.mmu 的 RiscvMMU 实例 |
| L1 I/D、L2、L3 | CPU 的 icache、dcache 与系统的 l2_caches[i]、l3 |
| 互联、控制器 | makeBareMetalXiangshanSystem 内的 membus 与内存子系统的 mem_ctrls[i] |

| 输入 / 选项 | Decode / Rename 宽度（条/周期） | 整数 / 浮点物理寄存器数 |
|---|---:|---:|
| GEM5-1 默认 | 6 / 6 | 224 / 192 |
| GEM5-1 ideal | 10 / 10 | 384 / 320 |
| zenas-dev 默认 | 6 / 6 | 224 / 192 |
| zenas-dev ideal | 8 / 8 | 256 / 320 |

参数沿 huanjianV1Core → RiscvO3CPU → BaseO3CPU 定位。GEM5-1 默认宽度来自 BaseO3CPU.py 的 152、158 行，理想配置来自 xiangshan.py 的 319、320 行，整数 / 浮点寄存器覆盖分别在 331、332 行。zenas-dev 对应的默认宽度位于 141、147 行，理想覆盖位于 317、318、326、327 行。四套输出均保留声明默认、条件分支及当前有效值。向量、谓词、向量缓冲、条件码和可重命名杂项物理寄存器数分别为 384、32、128、0 和 40，四次均保留源码默认来源。

Decode 对 Rename 的边界合并在 CPU 注入的 decodeQueue。RAT、物理寄存器文件和自由表由 CPU 组织，Rename 使用这些对象；cpu.cc 的 renameMap[tid].init(regClasses, &regFile, &freeList) 直接给出三者关系。可核对 UnifiedRenameMap 的类别索引接口，但未从中取得 RAT 的物理分库数和读写端口配置；检查器在该项显示“未知”。后续各轮继续使用 R1 的归属与参数证据。

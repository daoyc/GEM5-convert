# 第 7 轮　访存队列、缓存、总线与内存控制器

两份源码均以 `configs/example/xiangshan.py` 为入口。覆盖清单依据当前输入的类声明、入口参数和条件赋值生成。每次切换 ideal 配置会重算当前值，同时保留声明值、备选赋值与各自的行号。

| 参数 | 两模型源码默认 | GEM5-1 选择 ideal | zenas-dev 选择 ideal |
|---|---:|---:|---:|
| ROB | 160 | 384 | 256 |
| LQ | 80 | 128 | 128 |
| SQ | 64 | 64 | 64 |
| Store Buffer | 16 | 48 | 24 |
| D-cache MSHR | 16 | 32 | 32 |
| L3 容量 | 16MB | 32MB | 16MB |

GEM5-1 的队列声明见 `src/cpu/o3/BaseO3CPU.py:190`、191、196、238 行，ideal 赋值见 `configs/example/xiangshan.py:327` 至 334 行。zenas-dev 对应声明在 179、180、185、227 行，赋值在 322 至 329 行。两份源码的 D-cache MSHR 覆盖分别在入口脚本第 397、379 行。两个入口都会在同时选择 ecore 和 no-L3 时将 L2 设为 4MB。

- LSU 子图补入按行与字节范围匹配的 Store Buffer 转发，引用 `src/cpu/o3/lsq_unit.cc` 对 `recordForward` 的实际调用。LSQ 的返回路径关联到 `src/cpu/o3/lsq.cc` 的 `completeDataAccess(mainPacket())`。
- I/D walker 分开核对。两条证据链各记录八处位置，涵盖 `src/arch/riscv/RiscvMMU.py` 的 walker 端口绑定、`configs/common/CacheConfig.py` 的 walker cache 类型和构造、`src/cpu/BaseCPU.py` 的 CPU 侧连接及 mem_side 端口列表、其 `connectCachedPorts` 实现、tol2bus 和 L2 的绑定。L2 子图可播放 I/D 页表缓存未命中后由 L2 命中返回的独立场景。
- 四种缓存的同一行在途缺失场景保留各自边 ID。请求合并的依据是 `src/mem/cache/base.cc:490` 的 `allocateTarget`，回包入口依据是同文件第 3285 行。总线请求和返回分别依据 `src/mem/coherent_xbar.cc:349` 保存端口、462 行查表，以及对应的 `schedTimingResp`。
- 常规内存总线连接见 `configs/common/MemConfig.py:277`。选择 DRAMsim3 时，时序配置来自 `XSConfig.py:114` 和 `MemConfig.py` 的 `configFile` 赋值，反压与重试回放依据 `src/mem/dramsim3.cc:286` 及 168 行。选择 SimpleMemory 时，覆盖清单把尚未映射的具体后端事务时序标为未知。

**重建与验证**　运行 `python iterations/verify_memory.py 7`。两个源码树分别执行三次完整转换，均生成临时 JSON 和独立 HTML。已核对默认模式、ideal 模式，以及 ecore/no-L3 + SimpleMemory + 合成运行配置组合。断言检查上表当前值、源文件行片段、八处 walker 证据、回放边、L3 的条件移除、L2 的 4MB 覆盖和导入的 CPU 队列字段。运行样本为 `iterations/08-runtime.json`，没有执行 gem5 仿真。
